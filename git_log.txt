Architecture Decision Notes:
  - SparseIndex removed from DefaultStoreEngine because LSM-Tree SSTables each
    have their own .idx sparse index files, making a separate global index redundant
  - SSTable data stored uncompressed (text format) to support RandomAccessFile seek
    for efficient offset-based lookups; compression can be added at the SSTable level
    as a future optimization
  - LSM-Tree tombstone uses null value (not empty string) to distinguish "deleted"
    from "empty value", and contains() checks value != null
  - Replication uses push model: master writes locally then forwards to slaves;
    slave writes are applied locally without further replication to prevent loops
