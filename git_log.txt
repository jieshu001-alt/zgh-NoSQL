Architecture Decision Notes:
  - DataFileManager deleted as dead code; LSM-Tree SSTables handle data file management
  - Compactor integrated into LSMTree.mergeLevel() for L2 cold data GZIP compression
  - L0/L1 SSTables stay uncompressed for fast random access via sparse index
  - SparseIndex serves as global key->SSTable lookup for O(1) get() when cache warm
  - LRU cache (10000 entries) provides read-through caching above LSM-Tree
  - Collection commands (C_SET/C_GET/C_DEL/C_KEYS) use "collection:key" prefix internally
  - SSTable tombstone uses null value (not empty string) for deleted key marking
  - Replication uses push model: master writes locally then forwards to slaves
  - Read load balancing: slaves serve GET/KEYS/EXISTS locally without master forwarding
  - Rotate based on SSTable file size (64MB): checkRotateAndCompress() runs every 10s,
    closes file -> creates new file -> submits old file to Compactor for async compression
  - Complex data types (List/Set/Map) stored as JSON: LPUSH/RPUSH/LPOP/RPOP/LLEN for List,
    SADD/SMEMBERS/SREM for Set, HSET/HGET/HDEL/HGETALL for Hash
  - All List/Set/Hash commands support cluster replication via ReplicateCallback
